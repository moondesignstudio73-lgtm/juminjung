# 낮 피드백 / 야간 이야기 분리

## 기존 하루 흐름

프론트 행동 → story 선택(있는 경우) → night 선택 → resolveDay → 컷신 → 큰 MorningReport → 다음 날.
resolveDay는 사건 적용, 인물 이야기 진행, Aura, 배급/전력/당직, 직원 효과, 시설 유지비/생산, 체류 종료, 관계와 로그, 엔딩 판정을 처리한다.

## 문제점

결과 화면이 자원·경영 목표·전체 로그·관계·결말 조건을 동시에 보여줬다. 행동 결과는 즉시 드러나지 않고 사건과 경영 통계가 섞였다. 체크인 자원은 일률적인 비용이 아니라 투숙객이 제공하는 물자이므로 예시의 식량 -2를 그대로 구현하면 실제 규칙과 달라진다.

## 새로운 낮 흐름

동일한 프론트 유지. 실제 행동 전후 차이를 읽어 자원, 투숙객, 객실, 행동 포인트와 호텔 상태 변화 및 활성화 효과를 짧게 알린다. 작은 현재 상태바의 변한 항목을 강조한다. 기존 DAY 1 배치 피드백도 같은 알림에 통합했다. 저장 불러오기/날짜 변경/야간 소비는 낮 행동 알림으로 재생하지 않는다.

## 새로운 야간 흐름

기존 상태 기반 사건 선택기를 유지한다. 자원, 위협, 관계/객실 거리, 이전 선택과 story/ending flags, 도감 대책에 따른 사건과 응답을 그대로 사용한다. 조용한 밤은 기본 휴식으로 이어지는 한 버튼을 표시한다. 실제 선택의 비용 계산과 기존 순찰 함수는 삭제하지 않았다.

resolveDay 계산은 그대로 한 번 실행한다. 새 lastNightPresentation은 읽기용 결과를 추가할 뿐이다. 인물 회복/악화, 신뢰, 체류 종료, 아버지 단서, 정전과 시설 중단에 맞는 최대 세 문장을 표시한다. 숫자는 선택한 야간 사건 자체의 자원 변화만 표시하고, 일일 소비는 장부로 보낸다. 첫날 컷신에서 투숙객이 있는데도 아무도 없는 듯한 문구가 나오지 않도록 보완했다.

다음 날 버튼은 하나다. 대형 정산 수치, 숙박 종료 도장, 결말 조건 목록은 밤 화면에서 제거했다. 장부 안의 저널에는 일일/입실/퇴실/자원/사건·조사/관계 필터, 최근 일일 소모와 시설 유지비·생산·직원 정산을 보존했다. 이미 열린 최종 사건만 저널에서 시작할 수 있고 미달 조건/진척 수치는 노출하지 않는다.

## 즉시 피드백 시스템

game/action-feedback.ts: getActionFeedback와 resourceChanges는 상태 차이로 ActionFeedback(type, title, changes, effects)를 만든다.
app/action-feedback.tsx: ResourceChangeToast, ChangeLines를 재사용한다. 알림은 4초간 표시되고 클릭을 가로채지 않는다. 리셋·불러오기에서 제거되며 phase 전환 시 지나간 낮 알림이 밤에 남지 않도록 한다.
game/night-presentation.ts: 실제 사건 직후와 전체 야간 정산을 구분하여 사건 비용과 인물 결과를 구성한다.

## 테스트 결과

- TypeScript 및 511개 테스트 통과. Pages 빌드 통과(기존 500kB 번들 경고는 남음).
- 테스트에서 체크인 실제 의약품 증가/가짜 식량 비용 없음, 객실 이동, 시설 건설, 무변화, 날짜 전환 알림 억제, 사건 비용과 일일 소비 분리, 정산 중복 방지, 구/신 저장 복원, 연료에 따른 사건 선택을 확인.
- 실제 브라우저 DAY 1 리암 205호/벤 206호 체크인: 의약품·식량·물 등 실제 받은 물자와 객실/인원 증가 표시.
- DAY 1 밤: 리암의 돌봄으로 벤의 상태가 나아졌다는 결과와 벤의 체류 종료만 표시. 통계/결말 조건/중복 자원 정산 없음.
- DAY 2 장부: 일일 소비 식량 2/물 2/연료 1과 이전 사건 기록 보존 확인.
- DAY 2 밤 → DAY 3 결과, 새로고침 후 여전히 DAY 3: 중복 정산 없음.
- 1366×768 및 390×844 화면 검토. 모바일 결과 화면 문서 크기 390×844, 가로 넘침 없음. 콘솔 warning/error 없음.
- 후반의 모든 사건 분기를 실제 브라우저로 완주한 것은 아님. 기존 엔진 회귀 테스트를 유지한다.

## 기존 세이브 호환

새 필드는 선택적이다. 구 report 저장에 필드가 없어도 간단한 대체 문구와 다음 날 버튼이 나온다. 기존 summary, eventHistory, resources, 관계, flags와 정산 guard를 유지한다. 즉시 알림은 저장하지 않는다.

## 배포

로컬 검증 결과이며 커밋/배포는 하지 않았다. 기존 GitHub Pages와 별도 Sites 설정 중 배포 대상은 확인 대기 중이다.
