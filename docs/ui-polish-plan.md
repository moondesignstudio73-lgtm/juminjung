# UI 정리 계획

## 진단

프론트 퀵메뉴는 CSS의 순서 선택자로 숨겨져 해금 기대감이 없다. 객실 표시가 프론트와 야간에서 중복되며 생성 주민의 이름/얼굴을 놓친다. 야간 운영은 공간 대신 목록이 중심이다. 장부의 식량 예상치는 신규 개인 유지비와 다른 계산을 사용한다. 시스템 메뉴는 저장 실패를 처리하지 않고 실제 저장과 무관하게 성공 안내를 띄운다. 슬롯 요약, 도움말, 키보드 접근성이 부족하다. 전반적으로 작은 글씨와 서로 다른 버튼 높이·위험 색상이 겹친다.

## 설계

- 바탕 #0b0d0b / 공간 #171b16 / 글자 #ede1ca / 황동 #c69b55 / 회복 #8eae96 / 위험 #d18a79.
- 기존 제목용 서체와 한국어 본문 서체 유지. 제목 24~32, 본문 14~16, 보조 최소 12px.
- 낮: 방문객 + 짧은 자원/수용 현황 + 고정 퀵메뉴. 밤: 층/시설 위치를 클릭하는 기능형 지도 + 가장 중요한 문제 하나.
- 객실은 같은 상태 표기와 주민 초상화를 재사용. 개방/파손/점유/추천은 색상 외 글자·아이콘으로 구분.
- 기본 행동 40px 이상, 주요 진행 48px 이상. 진행은 황동, 위험 확정은 붉은색, 보조는 테두리.
- 저장 실패를 숨기지 않는다. 슬롯에는 주민/개방 객실/최근 기록을 표시. 도움말은 범주별 접기.
- 툴팁/선택/설정은 UI 상태로 유지. 새 게임은 타이틀로 한정. 기존 게임 계산은 변경하지 않는다.

## 순서

P0 공통 계층 → P1 퀵메뉴 → P2 객실 → P3 주민 → P4 시설 → P5 야간 지도 → P6 결과 피드백 → P7 시스템 메뉴 → P8 도움말/해금 → P9 기존 자산·절제된 전환. 실제 DAY 1/3/5/10 및 PC 세 해상도·작은 창에서 검증한다.

## 제외

새 시설/재화/직업/사건은 만들지 않는다. 장식용 그래픽 대량 생성은 하지 않는다. 별도의 Sites 배포 대상은 기존 공개 GitHub Pages와 불일치하므로 임의 배포하지 않는다.
