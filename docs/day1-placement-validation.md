# DAY 1 객실 배치 튜토리얼 검증

## 분석

- 객실은 3층 × 10칸 좌표를 가진다. roomNumber 차이가 아니라 position의 Chebyshev 거리로 Aura 범위를 계산한다.
- Basic Care: radius 1, injuryRecovery ADD 2. 자신의 객실과 좌우·위아래층·대각선을 포함한다. 205호의 실제 범위는 104/105/106/204/205/206/304/305/306이다.
- 101호는 101/102/201/202에 닿는다. 202~209호의 도달 객실 수는 같다. 따라서 205/206은 안내용 추천이며 독점적인 위치 보너스가 아니다.
- day-manager는 부상 판정 없이 범위 안 투숙객의 Health를 회복시킨다(최대 100). 부상자만 회복한다는 기존 설명을 수정했고 계산 규칙은 바꾸지 않았다.
- 끝방은 주변 칸이 적지만 완전 격리나 감염 차단 보너스가 없다. 설명에서 이를 명시한다.

## 구현

- Guest.placement: tags / recommended(CENTER 또는 EDGE) / avoid / reason. 선택적 데이터이므로 기존 저장과 호환된다.
- placement-guidance는 실제 Aura 엔진의 범위를 재사용한다. 공개된 지원형 Aura를 가진 다른 손님도 추천을 받으며 숨겨진 특성은 추론에 쓰지 않는다.
- 새로운 DAY 1 첫 일반 방문객은 리암 모건(간호사, Basic Care)으로 고정했다. 이미 생성된 저장의 손님은 바꾸지 않는다.
- 205/206 추천 배지, hover·키보드 focus·선택에 따른 객실 비교, 실제 범위 강조, 능력 배치 팁을 기존 배정 화면에 통합했다.
- 추천 외 빈방도 자유롭게 선택할 수 있다. DAY 1 체크인 완료 후 유형별 안내가 4초간 표시되며 진행을 막지 않는다.
- 객실 이동에는 첫 체크인 안내를 숨긴다. 이동·DAY 2 이후 배정은 기존 기능을 유지한다.
- 기존 어두운 녹색과 금색, 서체를 유지했다. 형광 강조/화살표/모달 추가 없이 작은 배지와 지도 하단 설명으로 구성했다.

## 플레이 검증

독립적인 로컬 주소(4192)를 사용해 기존 4191과 공개 게임의 저장을 변경하지 않았다.

- 신규 시작 → 리암 → 체크인 → 205/206 배지 확인: 통과.
- 205/101/202 선택에 따른 중앙/끝/일반 설명: 통과.
- 205/101/202 각각 체크인과 세 가지 피드백: 브라우저에서 통과.
- 수동 슬롯에 배치 전 상태 저장 후 반복 복원: 통과.
- 202호 배치 후 새로고침, 투숙객에서 방 확인 및 205호 이동: 통과.
- DAY 1 밤 → DAY 2 → 새 손님 206호 체크인: 통과.
- 1366×768: 비교 설명·추천·확정 버튼을 실제 화면에서 확인. 초기 버튼 밀림을 설명 축약으로 수정.
- 390×844: 화면 밖 문서 가로 넘침 없음. 객실 지도만 가로 스크롤, 비교 설명은 고정. 추천 배지의 텍스트가 카드 아래로 넘치던 행 높이를 수정해 카드 안에 들어옴을 확인.
- 브라우저 warning/error 로그: 없음.
- TypeScript 검사 통과, 테스트 506개 통과, Pages 빌드 통과. 기존 500kB 초과 번들 경고는 남아 있다.

## 남은 문제

- 1층 경비/시설 주변 보너스 등은 실제 계산 규칙이 없으므로 추가하지 않았다. 실제 효과가 도입될 때만 배치 유형을 확장한다.
- 모바일 지도는 30개 방의 공간 관계를 유지하기 위해 가로 스크롤이 필요하다.
- 이번 보고서는 로컬 구현·검증 결과다. GitHub Pages와 저장소 내 별도 Sites 설정의 배포 대상 확인 전에는 배포하지 않는다.
