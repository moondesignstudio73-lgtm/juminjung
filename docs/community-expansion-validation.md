# NPC 장기 거주와 객실 복구 MVP

## 기존 NPC 체류 구조

일반 방문자는 1~7박을 무작위로 배정받았고 resolveDay가 remainingNights를 줄여 자동 퇴실시켰다. 주요 스토리 인물은 storyLockedResident로 보호됐으며 같은 카운터가 사건 진행 시계로도 쓰였다. 기존 업무·Aura·자원 계산은 STAYING과 실제 객실 배정 여부를 기준으로 한다.

## 삭제한 랜덤 숙박일 시스템

일반 방문자의 랜덤 숙박일 추첨과 만료 퇴실을 제거했다. 호환용 stayDuration/remainingNights 필드는 일반 신규 주민에게 0으로 남긴다. 일반 사건 기록은 거주 3일째 갈등, 7일째 정착 기록으로 분산했다. 주요 스토리 시계와 명시적 출발 사건은 유지한다. 일반 방문자 대사의 ‘N박 요청’도 장기 거주 요청으로 교체했다.

## 새 장기 거주 구조

일반 NPC는 RESIDENT. 기존 STAYING 상태는 객실·Aura·업무 호환을 위해 유지한다. TEMPORARY는 특수 스토리용이며, EXPELLED/LEAVING/MISSING/DEAD 타입을 준비했다. 기존 STORY_LOCKED도 호환 유지한다. 모든 실종·재등장 사건을 새로 구현한 것은 아니다.

## NPC 퇴실 구조

프론트 투숙객 상세와 ‘주민과 배급’ 상세에서 퇴실을 요청한다. 확인 전에는 상태를 변경하지 않는다. 확정하면 객실과 Aura 및 업무 배정이 정리되고, 재방문을 막으며 EXPELLED로 기록한다. 남은 주민의 신뢰는 최대 2 감소한다. 작별 대사와 실제 담당 공석을 기록하며 즉시 소비 예상치에도 반영한다. 이전 단계 읽기 전용 화면에는 실행 버튼이 없다.

## NPC 직업/특성 구조

community에 job, traits, consumption(food/water), repairsCompleted를 추가했다. 기존 skills, 건강, 스트레스, 성격·숨은 특성, 관계 데이터는 재사용한다. 기존 18개 일반 직업에 배관공을 더했다. 방 복구는 목수·배관공·청소 담당·전기기사·정비공의 실제 전문 분야를 사용한다.

- 전문 분야 일치: 기본 부품과 시간 50%, 소수는 올림, 부품 최소 1.
- 꼼꼼함: 부품 -1(최소 1), 시간 +15분.
- 서두르는 손길: 시간 -30분(최소 30분), 부품 +1.
- 차분함: 표준 비용/시간.

개인 작업 스타일은 인물 ID로 결정해 로드할 때 다시 뽑히지 않는다. 부상·질병·탈진·기존 작업 수행 상태는 기존 근무 가능 판정에 연결된다. 도움을 준 주민은 스트레스 +8과 복구 횟수를 기록한다. 새로운 성공 확률이나 급여 규칙은 추가하지 않았다.

## 초기 객실 구조

201·204·205·206·207호만 개방한다. 끝 객실과 기존 205/206 추천을 유지하기 위한 선택이다. 나머지 25개는 이유가 있는 파손/봉쇄 상태다. 전체 물리 객실 수는 30개로 유지한다.

## 객실 복구 시스템

| 파손 | 직접 부품 | 약품 | 직접 시간 | 전문 도움 |
|---|---:|---:|---:|---|
| 수도 | 4 | 0 | 180분 | 배관공 |
| 문·벽 | 3 | 0 | 150분 | 목수 |
| 곰팡이 | 1 | 2 | 120분 | 청소 담당 |
| 전기 | 4 | 0 | 180분 | 전기기사 |
| 구조 | 6 | 0 | 240분 | 정비공 |

야간 객실 구역에서 선택 → 직접/주민 도움 비교 → 복구 시작. 같은 작업에서 자원과 시간을 확정 소모하고 방을 해금한다. 자원 부족·남은 시간 부족·사용 중·이미 복구·정산 단계에서는 실행할 수 없다. 도움을 줄 전문 NPC가 없어도 직접 복구할 수 있다. 진행률을 따로 적립하는 다일 작업은 MVP에 넣지 않았다.

2층 일반 손상은 DAY 3, 구조 손상과 1층은 DAY 10, 3층은 DAY 18부터 접근 가능하다. 자원·시간 비용도 함께 적용된다. 공용부 보수가 신규 잠긴 객실을 우회 해금하지 않도록 분리했다. 기존 저장의 유형 없는 손상 방에 대한 이전 보수 동작은 유지한다. 만실이면 체크인을 막고 퇴실/야간 복구/거절을 안내한다. 방문자를 대기시켜 같은 낮에 긴급 복구하는 기능은 추가하지 않았다.

## 자원 소비 밸런스

기본 식량 1, 물 1. 일반 정비공·목수는 식량 2. 주요 스토리 인물의 기존 기본 수요 1은 유지해 기존 사건 밸런스 변동을 줄였다. 개인 수요를 실제 Aura → 주방 절약 → 배급 계산에 연결했다. 물도 개인 합계를 기존 절약 정책에 연결한다. 화면 예상치와 야간 정산은 같은 함수를 사용한다.

개인 전력/약품 정액 소비, 과밀 페널티, 시설별 권장 인구, 새 재화는 이번 MVP에서 추가하지 않았다. 기존 발전기 연료·전력 회로·치료 비용은 그대로 유지한다. 모든 자원을 UI에 임의의 유지비로 나열하지 않는다.

## 세이브 마이그레이션

기존 일반 TEMPORARY는 RESIDENT로 변환한다. 이미 퇴실한 인물을 부활시키지 않는다. 기존에 쓰던 30개 방을 소급해 잠그지 않는다. 새로운 복구 정보·완료 상태·개인 유지비·작업 횟수를 저장하고, 잘못된 개인 소비 수치는 안전한 범위로 복구한다. 저장 슬롯과 기존 버전 번호는 유지한다.

## 테스트 결과

전체 545개 통과, TypeScript 검사·프로덕션 빌드 성공. 기존 큰 JS 청크 경고는 남는다.

- A: 일반 주민 10회 실제 resolveDay 정산 후 자동 퇴실 없음 — 자동 테스트 통과.
- B: 퇴실 시 객실/Aura/담당 해제·소비 중단·중복 실행 방지 — 자동 테스트 통과. 브라우저에서 취소 후 유지, 이후 DAY 4 확정 퇴실과 식량/물 예상 0 확인.
- C/D: 초기 5개 방, 25개 잠금, 5종 파손 요구조건 — 자동 테스트 및 DAY 1 화면 확인.
- E: 직접 복구 비용/시간/해금 — 자동 테스트. 브라우저 DAY 3에 202호 직접 복구, 21:15→23:45, 개방 객실 6개 확인.
- F: 전문 NPC 비용·시간 효율, 작업 기록, 부상자 차단 — 자동 테스트 통과. 모든 직업을 브라우저에서 각각 실행한 것은 아님.
- G: 만실 배정 거부와 일반 보수 우회 차단 — 자동 테스트 통과. 만실 브라우저 시나리오는 별도 미실행.
- H: 기존 저장의 주민/30개 객실 보존, 새 복구 저장 — 자동 테스트 통과. 기존 DAY 5 저장 로드 및 새 DAY 3 복구 후 브라우저 새로고침 유지 확인.

브라우저에서 DAY 1→4를 실제 클릭/키보드로 진행했다. 1366×768 객실 오버레이에서 가로 넘침 없이 내부 스크롤로 정보를 접근할 수 있음을 확인했다. 콘솔 error/warn 없음. 모바일 전체 흐름과 장기 20명 이상 호텔은 별도 검증이 필요하다.
