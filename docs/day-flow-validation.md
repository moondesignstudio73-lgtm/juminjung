# JUJU HOTEL 하루 흐름 개편 — 2026-09-04

## 기존 하루 구조

프론트 응대 → 야간 호텔 지도 → 스토리/야간 사건 → resolveDay → 결과 장면. 기존 미커밋 발전기 자동화 작업을 보존하고 그 위에 표시·진행 레이어를 추가했다.

## 문제점

방문객 응대와 전체 자원·관리 메뉴의 목적이 섞여 있었다. 야간에는 정상 시설까지 직접 열어 보게 됐고, 다음 날의 생활 관리가 별도 단계로 구분되지 않았다.

## 새 Day Flow

아침 보고 → 방문객 응대 → 주민과 배급 → 필요한 호텔 운영 → 밤의 사건 → 다음 날 보고.

- GameState.dayFlow: day, stage, visited, morningBrief, operationLocation.
- phase는 기존 계산·사건 API를 위해 보존. currentDayStage/advanceDayFlow로 표시 순서만 조율한다.
- 미래 단계는 잠금. 이전 단계 열람은 읽기 전용이며 정산·비용·선택을 되돌리지 않는다.
- 자동 저장은 기존 모든 상태 변경 저장 훅을 사용한다.

## 1. 결과 보고

기존 lastNightPresentation과 DaySummary, 실제 발전기 경고에서 최대 5개 내용을 추출한다. 선택, 주요 사건, 주민 상태 악화/퇴실, 큰 사건 물자 변화, 오늘 위험을 표시한다. 퇴실 중복 문장을 제거했다. 읽은 보고는 morningBrief에 고정하여 이후 수리나 재열람으로 내용이 바뀌지 않는다. resolveDay에 주민 건강/스트레스 변화 기록도 보존한다.

## 2. 생활 관리

DAY 2부터 주민 초상화·이름·직업·중요 상태·담당과 전체 배급 정책을 표시한다. 주의 주민을 우선 4명까지, 모두 안정이면 최대 3명을 보여준다. 나머지는 펼쳐 보기와 스크롤로 확인한다. 상세에는 건강·스트레스·신뢰와 상태를 표시한다.

식량/물은 재고보다 예상 일수를 우선 표시한다. 수요는 기존 Aura·전력·직원·배급 계산을 조합한 예상치이며 이후 사건 때문에 실제 정산은 달라질 수 있다고 명시한다. 별도 물 제한 정책이나 개인별 배급은 만들지 않았다. 기존 물 수요 지급을 유지한다.

## 3. 운영 결정

실제 필요한 발전기 점검/위험, 객실·호텔 보수, 환자 확인, 낮은 정문 안전도와 선택 가능한 탐사만 목록에 노출한다. 정상 자동 관리 발전기는 작은 한 줄로 축약한다. 시설을 선택하면 기존 NightManagement의 해당 공간만 표시하고 운영 목록으로 돌아온다. 이동·수리 시간과 발전기 지속 배정/자동화는 유지된다.

## 4. 사건

기존 StoryChoiceScene/NightEvent를 유지하되 별도의 밤 단계로 연결한다. 전체 자원·시설·관계·저널을 기본 노출하지 않는다. 선택의 실제 결과는 다음 날 보고로 이어진다. 기존 직업·Aura·조사·스토리 조건을 제거하지 않았으며 새 사건이나 가짜 직업 선택지는 추가하지 않았다.

## 조건부 단계와 자동 스킵

DAY 1은 생활/운영 단계 없음. DAY 2 생활 관리 추가, DAY 3부터 실제 운영 문제 노출, DAY 4 발전기, DAY 5 지속 담당 배정. 필요 없는 운영은 자동 생략한다. 예방 수리나 업그레이드를 원하는 플레이어는 배급 단계에서 운영을 직접 열 수 있다. 정상 시설의 매일 확인 클릭은 요구하지 않는다. 탐사는 DAY 8 이후 가능한 주민과 미실행 조건이 있을 때 표시한다.

## 기존 시스템 연결

resolveDay·visitor queue·daily survival·night/story event·facility·hotel action·staff operation·room·Aura·investigation·codex·relationship·save 계산을 유지했다. 기록 보관소는 진행 화면에서 분리하고 이전 기록을 추가로 펼칠 수 있다. 기존 고급 패널은 선택적으로 접근할 수 있게 남겼다.

## 변경 파일

- app/page.tsx: 프롤로그부터 각 단계/방문객/시설/사건 연결, 이전 화면 읽기 전용 열람.
- app/night-management.tsx: 시설 내부 임베드 지원.
- game/types.ts / game/save-manager.ts: 단계 및 보고 저장, 구세이브 이관.
- game/day-manager.ts: 새 날 보고 단계 초기화, 실제 주민 변화 기록.

## 저장 호환

기존 desk→방문객, night_management→운영, story/night→사건, report→보고로 복원한다. 이미 정산된 밤을 다시 실행하지 않는다. 현재 단계·배급·시설 위치·경과 시간·자원을 유지한다. 보고 스냅샷이 없는 과거 저장은 기존 야간 결과에서 표시 내용을 재구성한다.

## 테스트 결과

전체 자동 테스트 535개 통과, TypeScript 검사 및 프로덕션 빌드 성공. 빌드에는 기존 500 kB 초과 JS 청크 경고가 남아 있다. 최종 빌드의 1366×768 생활 화면에서도 진행 버튼과 선택적 운영 진입 버튼이 화면 안에 표시됐으며 콘솔 error/warn은 없었다.

A DAY 1 단순 진행, B DAY 2 생활, C 비소모성 예상치/표시, D 빈 운영 생략, E 문제 표시, F 자동 시설 축약, G 사건 진행 보호, H 다음 날 선택 회수, I 단계 저장 복구를 검증했다. 보고 중복/고정, 이전 저장 매핑, 선택 확정 후 운영 재개 금지도 포함한다.

## DAY 1 플레이 결과

신규 게임에서 첫 보고 → 리암 체크인 → 205호 추천 오버레이 → 나머지 응대 → 첫날 밤 → DAY 2 보고를 직접 진행했다. 고급 관리 및 자원 집계 없이 방문객/객실이 중심이었다.

## DAY 3 플레이 결과

생활 관리 후 호텔 보수 필요 한 항목 표시. 객실 진입 → 부품 6→4, 호텔 상태 60→68, 작업 60분 → 운영 복귀 시 해당 항목 제거를 확인했다. 이전 주민 화면은 읽기 전용이었다.

## DAY 5 플레이 결과

에단 체크인 → 주민 2명과 배급 → 발전기 점검 → 지속 담당 배정 → 운영 화면의 정상 자동 관리 한 줄로 축약을 확인했다. 생활 단계 수동 저장을 DAY 11에서 다시 불러와 DAY 5/주민 2명/제한 배급/생활 단계가 복구됐다.

## DAY 10 플레이 결과

DAY 1부터 실제 클릭 흐름으로 DAY 10까지 진행했다. 발전기 지원·정문 경계·선택적 탐사의 세 항목만 운영 목록에 나타났다. 탐사 준비가 기존 직원 drawer에 직접 연결되는 것을 확인했다. 발전기 수리를 미루고 밤으로 진행하면 정전 사건, 이후 DAY 11 보고에서 선택과 주민 악화가 회수됐다. 탐사 출발 자체나 모든 메인 스토리 분기를 이 플레이에서 실행한 것은 아니다.

## 시각·반응형 검증

1366×768, 1920×1080, 2560×1440에서 생활 화면을 직접 확인했다. 주요 내용과 진행 버튼이 한 화면 안에 들어왔고 가로 overflow가 없었다. 기존 초상화와 짙은 녹색·황동색, 0.24초 전환을 사용하며 reduced-motion에서는 전환을 끈다. 브라우저 error/warn 없음.

## 남은 문제

고급 직원/탐사 drawer는 기존 밀도가 남아 있다. 독립 물 배급 정책, 개별 배급, 관계/도감 전용 새 단계, 새 직업 사건과 시설별 신규 문제는 이번 MVP에 포함하지 않았다. DAY 5 에단의 기존 체류 계약이 짧으면 위임 학습 기간도 짧아지는 점은 다음 밸런스 검토 대상이다. 모든 메인 스토리 분기와 20명 이상 실제 장기 플레이는 별도 검증이 필요하다. 큰 JS 번들 경고도 남는다.

이번 변경은 로컬 검증본이다. 공개 GitHub Pages와 별개인 Sites 설정의 배포 대상을 임의로 바꾸거나 배포하지 않았다.
